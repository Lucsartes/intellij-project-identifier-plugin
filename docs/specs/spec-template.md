How to write a spec (delete this comment when you use the template):

A spec says WHAT the plugin does for the user and WHY. It is written for a user or product owner, and it
must stay true across refactors: it changes only when user-visible behavior changes.

- Every statement must be checkable by using the plugin, without reading the source code.
- No class, file, package, library or IDE-API names. Those belong in an ADR (../adrs/).
- No implementation mechanics (threads, caches, storage formats, polling intervals).
- No exact tuning values unless they are a product promise: write "low opacity", not "15 %".
- No list of source files and no change history: specs describe today's behavior, CHANGELOG.md records
  what changed and when, and the ADRs linked below lead to the code.
